# singularidade-data-bridge v0.8.0 — Firebird fidelity, stable output, catalog JAR

**Status:** approved in chat on 2026-10-21 (design) — written 2026-10-22.
**Origin:** handoff from the `sgh-web` team, who want to replace the Firebird MCP server in their
entity-mapping skills with data-bridge: read a table's structure while mapping a JPA entity and keep
that metadata versioned in their git repository.

## 1. Goals

1. `metadata.json` carries everything an entity-mapping agent needs from a Firebird table:
   UNIQUE and CHECK constraints, triggers, the generator behind each column, the column's domain
   (with its NOT NULL / DEFAULT / CHECK), character set and collation, and the exact Firebird type.
2. `ddl.sql` / `triggers.sql` for Firebird are faithful and replayable with `isql`.
3. Several tables extracted in one JVM run; a missing table or schema is an error with the documented
   exit code.
4. An opt-in stable output mode whose files can be committed and diffed without noise.
5. Credentials can be passed outside the JDBC URL.
6. Fixed, parameterized queries read from a file (for data dictionaries such as SGH's
   `TBSGHTABELAS` / `TBSGHCOLUNAS`), and a second JAR without free-form SQL.
7. No known CVE in shipped dependencies; the HTTP daemon (`serve`) is removed.

Success = release `v0.8.0` on GitHub with both JARs, integration tests on Firebird 3 (the SGH engine)
covering every item, and a handoff back to `sgh-web` with the release link and the commands.

## 2. Decisions already taken (do not re-litigate)

- **`serve` is removed** (owner decision 2026-10-21). Nobody in our repos uses it; it is the only user
  of Javalin/Jetty 11 (EOL, CVE-2026-2332 fixed only in 11.0.29, not on Maven Central) and HikariCP.
  Remote databases keep working through the normal CLI commands.
- **Two JARs per release:** `data-bridge-vX.Y.Z.jar` (all commands) and
  `data-bridge-catalog-vX.Y.Z.jar` (no free-form `query`; `run-query` with file-based queries only).
  Both bundle the five JDBC drivers.
- **Default output does not change** for existing consumers (our `mcp-tool-from-table-*` skills read
  `foreignKeys[].refTableColumns`; `integras-digital/db-snapshots/*/refresh.sh` runs `extract-all`
  with the current flags). Everything new is additive or opt-in, except the explicit behavior changes
  in §9.
- **Scope = Firebird + driver-agnostic features.** Gaps of MySQL/Oracle/MSSQL (UNIQUE/CHECK, MSSQL DDL,
  sample syntax) stay out.
- **Generators are never guessed by name.** Only identity columns and trigger dependencies count.
- **SGH-specific queries live in the consumer repo**, not in data-bridge.
- Supported Firebird versions: **3.0+** (target SGH = 3.0.5; FB5 is on the horizon). FB 2.5 is not
  supported (the catalog lacks identity columns).

## 3. Firebird catalog reader

New package `digital.singularidade.databridge.source.jdbc.firebird`:

| Unit | Responsibility |
|---|---|
| `FirebirdCatalog` | Reads `RDB$` system tables for one table into an immutable `FbTable` model. One read per table per run (cached in `JdbcSource`). |
| `FbTable` + nested records | Model: columns, domains, constraints, indexes, triggers, generators, comments, database default charset. |
| `FirebirdTypes` | Renders the native type (`NUMERIC(15,2)`, `BLOB SUB_TYPE TEXT`, …) from `RDB$FIELDS` codes; maps to the normalized `sqlType`. |
| `FirebirdTriggerType` | Decodes `RDB$TRIGGER_TYPE` into timing + events (`BEFORE`, `[INSERT, UPDATE]`). |
| `FirebirdNames` | `isSystemGenerated(name)`: `INTEG_n`, `RDB$PRIMARYn`, `RDB$FOREIGNn`, `RDB$n`. |

Both `JdbcSource` (metadata.json) and `FirebirdDdlBuilder` (ddl.sql) consume `FbTable`, so the two
outputs cannot disagree.

Catalog facts the reader relies on:
- Column type comes from the column's domain row in `RDB$FIELDS`; a domain is *named* when its name is
  not system-generated (`RDB$n` = implicit domain).
- Effective NOT NULL = column flag OR domain flag. Effective default = column default, else domain
  default. Both are reported with their origin (column vs domain).
- Text length is `RDB$CHARACTER_LENGTH` (characters), never `RDB$FIELD_LENGTH` (bytes).
- NUMERIC/DECIMAL = integer storage types (7, 8, 16, 26) with `RDB$FIELD_SUB_TYPE` 1/2 or negative
  scale; precision from `RDB$FIELD_PRECISION`.
- Index columns ordered by `RDB$INDEX_SEGMENTS.RDB$FIELD_POSITION`; descending = `RDB$INDEX_TYPE = 1`;
  expression index = `RDB$EXPRESSION_SOURCE`; inactive = `RDB$INDEX_INACTIVE = 1`.
- Index backing a constraint = `RDB$RELATION_CONSTRAINTS.RDB$INDEX_NAME`.
- FK rules from `RDB$REF_CONSTRAINTS`; Firebird stores `RESTRICT` for the default.
- CHECK source from the constraint's BEFORE INSERT trigger (`RDB$CHECK_CONSTRAINTS` →
  `RDB$TRIGGERS.RDB$TRIGGER_SOURCE`).
- User triggers: `RDB$SYSTEM_FLAG = 0` (check-constraint triggers carry flag 3).
- Generators used by a trigger: `RDB$DEPENDENCIES` with `RDB$DEPENDED_ON_TYPE = 14`.
  A generator is linked to a column only when the trigger body assigns it:
  `NEW.<col> = GEN_ID(<gen>, …)` or `NEW.<col> = NEXT VALUE FOR <gen>`. Identity columns link to
  `RDB$RELATION_FIELDS.RDB$GENERATOR_NAME`.
- Every query compares `TRIM(RDB$...)` names and orders explicitly — no reliance on `LIST()` order.

## 4. `metadata.json` contract 1.1 (additive)

`version` becomes `"1.1"`. New/filled fields (Firebird fills them; other drivers emit `null` / `[]`):

```jsonc
"columns": [{
  // existing fields unchanged …
  "sqlType": "text",                       // FB BLOB SUB_TYPE TEXT (was "varchar"); other BLOBs → "blob"
  "nativeType": "BLOB SUB_TYPE TEXT",      // exact Firebird type, e.g. "NUMERIC(15,2)", "VARCHAR(60)"
  "charset": "WIN1252",
  "collation": "WIN_PTBR",                 // existing field, now filled
  "domain": {                              // null when the column has no named domain
    "name": "DM_FLAG", "notNull": true, "default": "'F'", "check": "VALUE IN ('T','F')"
  },
  "sequence": {                            // existing field, now filled
    "name": "GEN_IDITENSESQ", "schema": null,
    "source": "trigger",                   // "trigger" | "identity"
    "trigger": "TRG_PRITENSESQ_BIU"        // null for identity
  },
  "generated": { "isIdentity": false, "isComputed": true, "generationExpression": "(VALOR * QTDE)" }
}],
"indexes": [{
  // existing fields …; expression indexes now have columns [] and:
  "expression": "(UPPER(NOME))",
  "active": true,
  "constraint": "FK_PRITENSESQ_PAI"        // PK/UNIQUE/FK this index backs, or null
}],
"uniqueConstraints": [{ "name": "UK_X", "columns": ["CODEXT", "EMPRESA"] }],   // now filled on FB
"checkConstraints": [{ "name": "INTEG_9", "definition": "(QTDE >= 0)" }],       // now filled on FB
"triggers": [{                             // new top-level array
  "name": "TRG_PRITENSESQ_BIU", "timing": "BEFORE", "events": ["INSERT", "UPDATE"],
  "position": 0, "active": true, "body": "AS\nBEGIN\n …\nEND", "generators": ["GEN_IDITENSESQ"]
}]
```

Definitions and defaults are reported without the leading `CHECK` / `DEFAULT` keyword.

## 5. DDL output for Firebird

`ddl.sql`, in this fixed order:

1. Header (provenance; database default character set).
2. Shared objects used by the table, sorted by name — `CREATE DOMAIN` for named domains and
   `CREATE SEQUENCE` for generators linked through triggers. Commented as "create once per database".
3. `CREATE TABLE` — columns by position:
   - named domain → the domain name, plus column-level overrides (NOT NULL, DEFAULT, COLLATE);
   - otherwise the native type, `CHARACTER SET` when it differs from the database default,
     `COLLATE` when it differs from the charset default, DEFAULT, NOT NULL;
   - `COMPUTED BY (expr)`; `GENERATED BY DEFAULT AS IDENTITY` (FB3) / `ALWAYS` (FB4+);
   - PK and UNIQUE inline, columns in key order, `USING [DESC] INDEX name` when the backing index is
     named differently or descending.
4. `CREATE [UNIQUE] [DESCENDING] INDEX` for indexes that back no constraint, sorted by name; expression
   indexes as `COMPUTED BY (expr)`; `ALTER INDEX … INACTIVE` for inactive ones.
5. `ALTER TABLE … ADD … FOREIGN KEY`, sorted; `ON UPDATE/DELETE` only for CASCADE, SET NULL and
   SET DEFAULT (RESTRICT / NO ACTION are the default and `RESTRICT` is not valid Firebird syntax).
6. `ALTER TABLE … ADD CHECK`, sorted.
7. `COMMENT ON TABLE` / `COMMENT ON COLUMN` (columns by position).

System-generated constraint names are never written (Firebird assigns new ones on replay).
`triggers.sql`: `SET TERM ^ ;` block with
`CREATE OR ALTER TRIGGER "T" FOR "TABLE" ACTIVE|INACTIVE BEFORE INSERT OR UPDATE POSITION n` + body,
sorted by timing, position, name.

## 6. CLI

- **Common connection options** (all commands): `--jdbc-url` plus `--user`, `--password-env VAR`,
  `--password-file PATH`. Passed as driver properties. Giving credentials both in the URL and in flags
  is `INVALID_ARGS`; a missing variable or unreadable file is `INVALID_ARGS`.
- **`extract`**: `--table` is repeatable; `--tables-file PATH` (one name per line, `#` comments). All
  names are resolved before anything is written: exact match, then the driver's unquoted-identifier
  case (upper on Firebird/Oracle, lower on PostgreSQL). Any miss → exit 11 listing every missing name.
  The resolved name is used for the output directory.
- **Schema check**: when `--schema` is given for a schema-based driver and it does not exist → exit 12.
- **`--stable`** (`extract`, `extract-all`): removes `generatedAt`, `generator`, `source.url`,
  `warnings`, `sample`, `columnStats`, `cardinality`, `tableInfo.approximateRowCount` and
  `foreignKeys[].refTableColumns`; system-generated names become `null`; lists sorted — columns by
  position, foreign keys by (refTable, fkColumns), indexes by (name, columns) with null names last,
  unique constraints by columns, check constraints by definition, triggers by (timing, position, name).
  Cardinality is not computed. `_index.json` drops `generatedAt`,
  `generator`, `source.url` and `totalRows`. DDL headers drop version, source, server and timestamp.
  `--stable` with `--sample-rows > 0` is `INVALID_ARGS`.
- **`run-query`** (new): `--file queries.sql --name NAME [--param k=v]... [--limit] [--timeout-sec]
  [--out]`. File format: blocks introduced by `-- name: <id>`, one statement each, `:param`
  placeholders (string literals, comments and `::` casts are skipped). Always read-only. Parameter values
  are converted to the type the driver reports for each placeholder. Missing or unknown parameters,
  unknown names and parse errors → `INVALID_ARGS`. Output identical to `query`.
- **`--sample-rows`** works on Firebird (`SELECT FIRST n`).
- Error JSON is produced by one helper for every command (escaped, password-redacted).

## 7. Query guard (`query` and `run-query`)

One `SqlGuard`, applied to a normalized copy of the SQL (comments, string literals, dollar-quoted
strings and quoted identifiers blanked out):
- more than one statement (`;` followed by anything) → rejected; a single trailing `;` is stripped;
- first keyword allowlist: read-only = `SELECT`, `WITH`, `EXPLAIN`, `SHOW`; `--writable` adds
  `INSERT`, `UPDATE`, `DELETE`, `MERGE`, `UPSERT`, `REPLACE`. Everything else is rejected — DDL keeps
  its existing message; `EXECUTE BLOCK`, `EXECUTE`, `EXEC`, `DO`, `CALL`, `SET`, `RECREATE`, … are
  rejected even with `--writable`;
- read-only: DML keywords anywhere are rejected (covers `WITH … DELETE` on drivers without read-only
  transactions);
- Firebird read-only: `GEN_ID(x, n)` with `n ≠ 0` and `NEXT VALUE FOR` are rejected (generators
  advance even inside read-only transactions).

## 9. Behavior changes (documented in release notes)

- `serve` and the HTTP API are gone.
- Missing table → exit 11 (was 0 or 13); missing schema → exit 12.
- Firebird `sqlType` of BLOB SUB_TYPE TEXT is `text` (was `varchar`), other BLOBs `blob` (was
  `binary`); expression indexes report `columns: []` + `expression`.
- `query --writable` rejects `EXECUTE`/`CALL`/`DO`/`SET`; read-only rejects DML keywords anywhere and
  Firebird generator increments.
- Firebird `ddl.sql` content changes completely (it is now correct).
