# singularidade-data-bridge v0.8.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution note:** this plan is executed natively by its author (the owner asked for autonomous
> execution through the release). Steps carry the tests, interfaces, SQL and algorithms verbatim;
> straightforward glue (picocli options, record plumbing) is specified precisely in prose.

**Goal:** Ship v0.8.0: faithful Firebird metadata + DDL, multi-table extract with real exit codes,
`--stable` output, credentials outside the URL, `run-query` with file-based parameterized queries,
a second JAR without free SQL, no `serve`, no known CVEs.

**Architecture:** A new `FirebirdCatalog` reads `RDB$` tables once per table into an immutable `FbTable`
model consumed by both `JdbcSource` (metadata.json enrichment) and a rewritten `FirebirdDdlBuilder`.
Cross-driver concerns (connection options, error output, table resolution, stable transform, SQL guard,
named queries) are small focused classes wired into the existing picocli commands. A second shade
execution builds `data-bridge-catalog.jar` from the same classes minus `QueryCommand`/`Main`.

**Tech Stack:** Java 21, Maven, picocli 4.7.6, Jackson 2.18.12, Jaybird 6.0.7, JUnit 5 + AssertJ,
Testcontainers 1.21.2 (`firebirdsql/firebird:3.0.14`, `postgres:16`).

**Spec:** `docs/superpowers/specs/2026-10-22-v0.8.0-firebird-fidelity-design.md`

## Review Focus

1. Quoted mixed-case Firebird names (`"TbMista"."Cod"`): resolution must find the exact name before
   case folding, and DDL must keep the quotes — pinned in Task 10 (resolution) and Task 8 (replay).
2. Table names containing `_` / `%` (JDBC pattern wildcards, e.g. `TB_X` vs `TBAX`): resolution must
   match exactly — pinned in Task 10.
3. Databases whose default charset is `NONE` (SGH) or columns with explicit `CHARACTER SET NONE`:
   DDL emits `CHARACTER SET` only when it differs from the database default — pinned in Task 7.
4. `--password-file` content with special characters and a trailing newline: only the final line break
   is stripped — pinned in Task 9.
5. `:param` look-alikes inside string literals, comments and PostgreSQL `::` casts must not become
   placeholders — pinned in Task 13.

SQL (bind `?` = table name; all names `TRIM`med in the select list):
```sql
-- relation
SELECT r.RDB$VIEW_SOURCE, r.RDB$DESCRIPTION FROM RDB$RELATIONS r WHERE r.RDB$RELATION_NAME = ?
-- database charset
SELECT TRIM(RDB$CHARACTER_SET_NAME) FROM RDB$DATABASE
-- columns
SELECT TRIM(rf.RDB$FIELD_NAME) AS name, rf.RDB$FIELD_POSITION AS pos, TRIM(rf.RDB$FIELD_SOURCE) AS src,
       rf.RDB$NULL_FLAG AS rf_nn, rf.RDB$DEFAULT_SOURCE AS rf_def, rf.RDB$DESCRIPTION AS descr,
       rf.RDB$IDENTITY_TYPE AS idt, TRIM(rf.RDB$GENERATOR_NAME) AS idgen,
       f.RDB$FIELD_TYPE AS ftype, f.RDB$FIELD_SUB_TYPE AS fsub, f.RDB$CHARACTER_LENGTH AS clen,
       f.RDB$FIELD_LENGTH AS flen, f.RDB$FIELD_PRECISION AS prec, f.RDB$FIELD_SCALE AS scale,
       f.RDB$SEGMENT_LENGTH AS seg, f.RDB$NULL_FLAG AS f_nn, f.RDB$DEFAULT_SOURCE AS f_def,
       f.RDB$VALIDATION_SOURCE AS f_chk, f.RDB$COMPUTED_SOURCE AS f_comp,
       TRIM(cs.RDB$CHARACTER_SET_NAME) AS cs_name, TRIM(cs.RDB$DEFAULT_COLLATE_NAME) AS cs_coll,
       cs.RDB$BYTES_PER_CHARACTER AS bpc,
       TRIM(fc.RDB$COLLATION_NAME) AS f_coll, TRIM(rc.RDB$COLLATION_NAME) AS rf_coll
  FROM RDB$RELATION_FIELDS rf
  JOIN RDB$FIELDS f ON f.RDB$FIELD_NAME = rf.RDB$FIELD_SOURCE
  LEFT JOIN RDB$CHARACTER_SETS cs ON cs.RDB$CHARACTER_SET_ID = f.RDB$CHARACTER_SET_ID
  LEFT JOIN RDB$COLLATIONS fc ON fc.RDB$CHARACTER_SET_ID = f.RDB$CHARACTER_SET_ID
                             AND fc.RDB$COLLATION_ID = COALESCE(f.RDB$COLLATION_ID, 0)
  LEFT JOIN RDB$COLLATIONS rc ON rc.RDB$CHARACTER_SET_ID = f.RDB$CHARACTER_SET_ID
                             AND rc.RDB$COLLATION_ID = rf.RDB$COLLATION_ID
 WHERE rf.RDB$RELATION_NAME = ?
 ORDER BY rf.RDB$FIELD_POSITION
-- constraints
SELECT TRIM(rc.RDB$CONSTRAINT_NAME), TRIM(rc.RDB$CONSTRAINT_TYPE), TRIM(rc.RDB$INDEX_NAME)
  FROM RDB$RELATION_CONSTRAINTS rc
 WHERE rc.RDB$RELATION_NAME = ? AND rc.RDB$CONSTRAINT_TYPE IN ('PRIMARY KEY', 'UNIQUE', 'FOREIGN KEY', 'CHECK')
 ORDER BY rc.RDB$CONSTRAINT_NAME
-- indexes and segments
SELECT TRIM(i.RDB$INDEX_NAME), COALESCE(i.RDB$UNIQUE_FLAG, 0), COALESCE(i.RDB$INDEX_TYPE, 0),
       COALESCE(i.RDB$INDEX_INACTIVE, 0), i.RDB$EXPRESSION_SOURCE
  FROM RDB$INDICES i WHERE i.RDB$RELATION_NAME = ? ORDER BY i.RDB$INDEX_NAME
SELECT TRIM(s.RDB$INDEX_NAME), TRIM(s.RDB$FIELD_NAME)
  FROM RDB$INDEX_SEGMENTS s JOIN RDB$INDICES i ON i.RDB$INDEX_NAME = s.RDB$INDEX_NAME
 WHERE i.RDB$RELATION_NAME = ? ORDER BY s.RDB$INDEX_NAME, s.RDB$FIELD_POSITION
-- foreign keys (referenced columns = segments of ref_index, read with the segment query by index name)
SELECT TRIM(ref.RDB$CONSTRAINT_NAME), TRIM(ref.RDB$UPDATE_RULE), TRIM(ref.RDB$DELETE_RULE),
       TRIM(uq.RDB$RELATION_NAME), TRIM(uq.RDB$INDEX_NAME)
  FROM RDB$REF_CONSTRAINTS ref
  JOIN RDB$RELATION_CONSTRAINTS rc ON rc.RDB$CONSTRAINT_NAME = ref.RDB$CONSTRAINT_NAME
  JOIN RDB$RELATION_CONSTRAINTS uq ON uq.RDB$CONSTRAINT_NAME = ref.RDB$CONST_NAME_UQ
 WHERE rc.RDB$RELATION_NAME = ? ORDER BY ref.RDB$CONSTRAINT_NAME
SELECT TRIM(s.RDB$FIELD_NAME) FROM RDB$INDEX_SEGMENTS s WHERE s.RDB$INDEX_NAME = ? ORDER BY s.RDB$FIELD_POSITION
-- checks (the BEFORE INSERT trigger carries the source)
SELECT TRIM(cc.RDB$CONSTRAINT_NAME), t.RDB$TRIGGER_SOURCE
  FROM RDB$CHECK_CONSTRAINTS cc
  JOIN RDB$RELATION_CONSTRAINTS rc ON rc.RDB$CONSTRAINT_NAME = cc.RDB$CONSTRAINT_NAME
  JOIN RDB$TRIGGERS t ON t.RDB$TRIGGER_NAME = cc.RDB$TRIGGER_NAME
 WHERE rc.RDB$RELATION_NAME = ? AND rc.RDB$CONSTRAINT_TYPE = 'CHECK' AND t.RDB$TRIGGER_TYPE = 1
 ORDER BY cc.RDB$CONSTRAINT_NAME
-- triggers + generator dependencies
SELECT TRIM(t.RDB$TRIGGER_NAME), t.RDB$TRIGGER_TYPE, COALESCE(t.RDB$TRIGGER_SEQUENCE, 0),
       COALESCE(t.RDB$TRIGGER_INACTIVE, 0), t.RDB$TRIGGER_SOURCE
  FROM RDB$TRIGGERS t
 WHERE t.RDB$RELATION_NAME = ? AND COALESCE(t.RDB$SYSTEM_FLAG, 0) = 0
 ORDER BY t.RDB$TRIGGER_NAME
SELECT DISTINCT TRIM(d.RDB$DEPENDENT_NAME), TRIM(d.RDB$DEPENDED_ON_NAME)
  FROM RDB$DEPENDENCIES d JOIN RDB$TRIGGERS t ON t.RDB$TRIGGER_NAME = d.RDB$DEPENDENT_NAME
 WHERE t.RDB$RELATION_NAME = ? AND COALESCE(t.RDB$SYSTEM_FLAG, 0) = 0
   AND d.RDB$DEPENDENT_TYPE = 2 AND d.RDB$DEPENDED_ON_TYPE = 14
 ORDER BY 1, 2
```
